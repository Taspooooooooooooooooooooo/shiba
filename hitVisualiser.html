HITBOX DIAGRAM
1

Client Fires

Client sends RemoteEvent:FireServer(origin, direction, timestamp) — nothing else. No damage value, no hit target. The client has zero authority.

↓
2

Timestamp Validation

Server checks |T_server − T_client| < MaxWindow. If timestamp is too old or in the future, the shot is dropped silently and flagged.

↓
3

Position Rewind

Server rewinds all nearby player positions to T_client using stored position history. Raycast runs against rewound positions, not current ones.

↓
4

Ray-Sphere Intersection

Server casts ray from origin along direction. Checks discriminant Δ against each hitbox sphere. First positive intersection wins.

↓
5

Sanity Checks

Verify distance ≤ WeaponRange. Verify shooter isn't dead. Verify rate limit not exceeded (shots/sec ≤ WeaponFireRate). Any failure → reject + log.

↓
6

Damage Calculation

Server computes D(r) × Z. Applies to target health server-side only. No client can modify this value.

↓
7

Death & Logging

If health ≤ 0, server fires death event → triggers 8s respawn, department spawn logic, SCP containment state update. Every shot logged regardless of outcome.
